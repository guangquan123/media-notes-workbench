# Media Notes Workbench 发布整改与验收 Runbook

## 发布目标

在一台没有 Node.js、npm、ffmpeg 的干净 Windows 10/11 x64 设备上，用户双击桌面图标后，可以完成首次配置、连接 AI、创建第一篇文档笔记；选择音视频时，内置工具可直接被服务发现，失败时有明确的修复路径。

## 已实施

- 首次启动向导按“选择用途 → 自动准备 → 连接 AI → 选择模型 → 验证完成”运行。
- 环境检查请求有并发锁，React Strict Mode 不会重复触发检查。
- 缺失组件按实际名称提示，存储不可用时隐藏错误的文档降级入口。
- 语音转文字模型列表不会因自动选中模型而重复请求。
- 腾讯云 ASR 在提交前校验 SecretId、SecretKey、地域和 COS 存储桶。
- 安装包复制 `tools/` 到应用目录，并在服务启动时自动加入 PATH。
- 新增 `release:check` 发布前置检查和 `--strict-media` 严格媒体门禁。

## 发布前操作

1. 准备合规的工具文件：
   - `tools/ffmpeg.exe`
   - `tools/yt-dlp.exe`
   - 如使用本地 Whisper，再放入对应 CLI 和模型文件。
2. 在干净依赖环境执行 `npm ci`。
3. 执行 `npm run release:check -- --strict-media`，不得有失败项。
4. 执行 `npm run package:windows:compile` 生成 Inno Setup 安装包。
5. 保存 `release/windows/<version>/app/package-manifest.json` 和安装包 SHA-256。

## 对抗式验收矩阵

| 场景 | 期望结果 |
| --- | --- |
| 首次双击桌面图标 | 启动进度可见，服务就绪后自动打开浏览器 |
| 已有服务/端口占用 | 不等待超时，提示端口占用并给出重试和日志入口 |
| 缺少运行文件 | 启动失败原因明确，提示重新安装或查看日志 |
| 文档用途 | 不要求 ffmpeg、yt-dlp 或转录配置，可创建第一篇笔记 |
| 音视频用途 | 环境检查发现内置 ffmpeg，后续转录验证可完成 |
| 平台视频用途 | 环境检查发现内置 yt-dlp，下载链路可用 |
| AI Key 错误/网络断开 | 当前步骤保留，错误靠近用户操作，不丢失已填信息 |
| 腾讯云字段缺失 | 提交前一次性列出缺少字段，不发起无效请求 |
| 重启/升级 | 笔记和配置保留，旧服务进程被正确回收 |
| 卸载 | 安装程序和快捷方式移除，用户数据按产品策略保留 |

## 当前发布门禁

仓库已经具备代码侧的发布检查和内置工具路径支持；但当前工作区没有 `tools/ffmpeg.exe` 与 `tools/yt-dlp.exe`，因此严格媒体门禁会阻断。这是有意的硬门槛，避免生成“能安装但音视频不可用”的客户版本。工具文件和许可证确认后，重新运行上述步骤即可进入正式批量交付。
