# 可跳过配置与能力门禁实施方案

## 1. 需求目标

首次打开工作台时，用户可以跳过暂时不需要的配置，不再因为钉钉、飞书、模型或转录服务不可用而被迫完成全部配置。用户进入具体功能后，系统再根据该功能的实际依赖检查配置；缺少依赖时明确说明需要配置什么，并提供进入参数配置页的入口。

## 2. 影响评估

### 状态与流程

- 首次引导从“所有步骤必须验证”调整为“环境可用即可完成，能力配置按需完成”。
- 未完成的模型、转录、连接器仍保留在 `requiredActions`，用于设置页和能力门禁展示，不能通过删除状态来掩盖缺失配置。
- 本机数据目录仍是硬阻塞项，因为没有它就无法可靠保存任务和 Markdown 文件；`ffmpeg`、`yt-dlp`、AI、转录和外部连接器均改为按能力阻塞。
- 完成引导后允许进入工作台；已完成的引导不会因为后来缺少可选能力而被 Layout 重定向回引导页。

### 功能依赖

| 能力入口 | 必要条件 | 缺失时行为 |
| --- | --- | --- |
| 文档笔记 | 本机存储、总结模型 | 阻止进入处理，提示配置模型 |
| 本地音频/视频 | 本机存储、总结模型、ffmpeg、可用转录方式 | 阻止进入处理，列出缺项 |
| 录音 | 本机录音存储；转换时复用总结模型、ffmpeg、转录 | 可录音但转换前拦截并引导配置 |
| 平台视频 | 总结模型、ffmpeg、转录、yt-dlp | 阻止进入处理，列出缺项 |
| 双源会议 | 总结模型、ffmpeg、转录 | 阻止进入处理，列出缺项 |
| 飞书/钉钉同步 | 对应连接器授权和验证 | 仅在用户选择外部同步时阻止；未配置时使用本地 Markdown |

### 兼容性与风险

- 现有设置页和 `/setup` 状态接口继续沿用，新增字段保持向后兼容。
- 门禁只负责进入功能前的体验校验，后端任务创建仍需保留自己的最终校验，避免绕过前端请求导致半成品任务。
- 配置页回跳通过 `returnTo` 参数实现；非法或缺失的回跳统一回到工作台首页，避免开放重定向。
- 能力状态读取失败时不猜测“已就绪”，而是显示可重试的配置提示。

## 3. 实施方案

1. **首次引导可跳过**
   - `SetupService.complete()` 只阻塞 `repair_storage`。
   - `Layout` 只依据 `status === completed` 判断是否放行工作台。
   - provider、capabilities、transcription、connector 步骤增加“跳过，稍后配置”；跳过时保存进度并进入下一步。
   - 环境步骤允许跳过非存储组件，存储不可用仍需修复。

2. **统一能力门禁**
   - 新增共享的能力依赖计算和前端 `CapabilityGate` 组件，统一读取 setup 状态、系统 readiness 和 AI/连接器配置。
   - 门禁页面展示功能名称、缺失配置、影响说明和“去参数配置”按钮；设置页完成后按 `returnTo` 返回原功能。
   - 在路由层包裹主要功能入口，避免每个页面重复实现同一套判断。

3. **配置页回跳**
   - `SettingsPage` 读取并校验 `returnTo`，返回按钮和配置完成后的入口都使用安全回跳。
   - 门禁根据缺项选择 `section=ai`、`section=connectors` 或 `section=storage`。

4. **验证**
   - 增加 setup 完成允许跳过和能力依赖计算的单测。
   - 运行服务端/客户端类型检查、相关单测、ESLint、生产构建和 `git diff --check`。

## 4. 验收标准

- 首次打开可以跳过钉钉、飞书、模型和转录配置并进入工作台。
- 未配置模型时点击文档入口会看到明确的“需要配置总结模型”提示，并能进入设置页。
- 未配置转录或本机组件时，音视频、录音转换、双源和平台视频入口不会创建任务。
- 未配置外部连接器时，文档仍能生成并下载 Markdown；选择外部同步时才要求连接器。
- 配置页完成后返回原来的功能入口，状态重新检查后可继续使用。
