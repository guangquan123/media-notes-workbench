# 可选外部连接器与本地 Markdown 输出方案

## 1. 需求判断

当前首次引导把“生成学习笔记”和“发布到飞书/钉钉”绑定在一起：任意用途都会进入连接器步骤，连接器授权失败会阻断首次使用。这个耦合会造成两个问题：

1. 外部平台不可用时，本地笔记能力也无法启动。
2. 用户只想生成文件时，被迫理解并配置与当前任务无关的第三方权限。

仓库已有本地文档服务，会把 Markdown 写入应用数据目录并提供受保护的读取接口；同时已有飞书、钉钉文档和待办服务。因此本次变更以“发布目标可选化”为边界，不改变笔记生成、历史记录和已有连接器协议。

## 2. 产品方案

### 默认流程

- 首次启动默认选择“文档笔记”等本地能力。
- 引导只检查本机存储和生成所需的 AI/转录能力。
- 不勾选“外部同步”时，不进入连接器配置，也不把连接器失败视为启动错误。
- 任务完成后生成 Markdown，保存在本机，结果页和历史页均可查看、下载。

### 外部同步流程

- 用户在首次引导或设置中明确选择“外部同步”后，才需要配置飞书或钉钉。
- 连接器验证失败只影响外部发布，不影响本地 Markdown 生成；引导完成前仍提示用户完成该能力的配置。
- 连接器就绪时沿用现有发布逻辑：飞书/钉钉文档，以及对应的待办创建。
- 连接器配置可在首次引导之后随时补齐，已生成的本地文件不受影响。

## 3. 技术影响

| 区域 | 现状 | 变更 |
| --- | --- | --- |
| Setup 状态机 | 所有能力都要求连接器 | 仅 `external_sync` 要求连接器 |
| Readiness | `connectorReady` 参与全局 ready | 本地运行时 `documentReady` 由本地文件能力保证；`connectorReady` 保留为外部发布状态 |
| 发布服务 | 本地运行时固定走本地，平台运行时走连接器 | 本地运行时按“连接器已就绪”选择外部发布，否则走本地 Markdown |
| 待办服务 | 本地运行时直接跳过 | 无连接器时跳过；连接器就绪时允许本地运行时创建外部待办 |
| 结果 UI | 默认文案为飞书文档 | 根据结果 URL 识别本地 Markdown，提供查看和下载 |
| 数据兼容 | 旧配置文件和历史记录可读 | 不迁移、不删除；旧状态只有选择外部同步时才新增阻塞项 |

## 4. 风险与控制

- 本地文件路径继续由 `LocalDocumentService` 生成 UUID 文件名并限制在 notes 目录内，避免路径穿越。
- 外部连接器凭据和现有授权流程不变；未配置时不发起第三方请求。
- 本地 Markdown 不嵌入外部媒体，保留现有引用和警告行为。
- “下载”通过同源受保护接口完成，不能绕过登录或读取任意文件。
- 本次不删除旧的连接器设置，也不改变已有文档 URL；历史记录仍可打开。

## 5. 验收标准

1. 新用户只选文档笔记时，首次引导不出现连接器阻塞，可完成并开始使用。
2. 飞书/钉钉授权接口不可用时，未选择外部同步的用户不再看到“服务暂时不可用”导致的启动失败。
3. 未配置连接器生成任务，任务状态为完成，`documentUrl` 指向本地 Markdown，文件存在于本地数据目录。
4. 结果页和历史页可查看并下载该 Markdown 文件。
5. 选择外部同步且连接器未就绪时，引导明确提示配置连接器；连接器就绪后仍能发布文档并创建待办。
6. 现有飞书/钉钉配置、历史记录、原文归档和媒体处理回归测试保持通过。
