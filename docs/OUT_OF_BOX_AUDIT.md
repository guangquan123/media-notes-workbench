# 开箱即用门槛与依赖审计

审计日期：2026-08-15

## 1. 结论

当前产品已经具备“检测后引导配置”的基础，但还没有达到“下载安装到第一次成功生成笔记都无需理解技术依赖”的完全开箱即用状态。

最短可用路径如下：

- 文档资料：输出连接器 + 总结模型。
- 本地音视频：输出连接器 + ffmpeg + 一种可用转录引擎 + 总结模型。
- 平台视频链接：本地音视频链路 + yt-dlp；部分站点失败时还需要浏览器 Cookie。
- 飞书、钉钉同步与机器人通知：都应保持为按需增强，不应阻塞本地基础使用。

运行模式会改变模型门槛：

- local 本地模式没有内置模型兜底，外部 OpenAI 兼容模型是核心依赖。
- miaoda 平台模式可以使用内置模型，外部模型只是可选增强。

因此，产品应以“本地输出为默认、按资料类型显示依赖、只暴露当前缺失项”为配置主线，而不是要求用户先理解所有技术组件。

## 4. 配置化设计原则

### 4.1 先选用户目标，再显示技术依赖

推荐把首次使用拆成四个用户选择：

1. 我只处理文档。
2. 我处理本地音视频。
3. 我还要处理平台视频链接。
4. 我需要同步到协作平台。

系统根据选择生成最小配置清单。用户不选择的平台、通知和云服务不出现红色阻塞状态。

### 4.2 使用安全默认值

- 默认输出：本地连接器。
- 默认通知：关闭。
- 默认平台下载：不要求配置 Cookie。
- 默认转录：自动选择已就绪的引擎；两者都可用时保留用户上次选择。
- 默认模型：平台模式使用内置模型；本地模式推荐常见 OpenAI 兼容服务预设，但不内置真实密钥。

### 4.3 渐进式披露

- 首屏只显示“是否可用、影响什么、下一步按钮”。
- API 地址、地域、模型参数、签名密钥等放入高级设置。
- 每个修复按钮跳到真实缺失项，不让用户在多个设置页之间猜测。

### 4.4 一次检测，多处复用

依赖检测应统一产生能力状态，而不是每个页面独立判断。建议后续形成统一的 capability readiness 响应，包含：

- capability：资料入口或输出能力。
- status：ready、action、optional、error。
- blockers：阻塞项列表。
- impact：受影响范围。
- action：修复入口。
- checkedAt：检测时间。
- version：检测到的组件版本。

### 4.5 凭证与配置安全

- 前端只读取是否已配置，不返回完整 API Key、SecretKey 或 Webhook 密钥。
- 编辑时留空表示保留旧值，避免用户每次重新输入。
- 连接测试与保存分开，失败时不切换当前连接器。
- 配置文件需要备份、恢复和迁移入口，但不能把密钥写入仓库或诊断包。

## 5. 本轮已落地

- 设置页新增“开始使用”，并作为默认分区。
- 自动并行读取环境、连接器、转录、模型、运行模式和通知状态。
- 主 readiness 失败时给出重试；可选接口失败时不让整页空白。
- 按“基础能力/按需能力”展示，不再让 yt-dlp 或通知阻塞文档和本地文件。
- 根据 local 或 miaoda 运行模式动态判断外部模型是否必需。
- 资料入口按端到端能力判断：解析或转录就绪但模型缺失时，不再误报“已就绪”。
- 修复按钮直接跳转到输出、转录、模型或通知设置。
- 本地连接器作为推荐默认路径；飞书和钉钉配置采用渐进式展开。
- 保留旧设置 URL，并兼容旧后端仅返回 larkCli 的 readiness 响应。
- 数据库模块改为全局提供，修复兄弟业务模块无法注入 `DRIZZLE_DATABASE` 的问题。
- local 模式启动时自动执行事务化、幂等的 PGlite schema 初始化，覆盖 7 张业务表、索引和外键。
- local 启动与构建统一设置 `VITE_RUNTIME=local`，避免误用妙搭平台容器和请求链路。
- local 请求自动保留 `/app/app_xxx` 前缀，静态代理转发到 Nest 前自动剥离该前缀。
- local 构建将平台容器、错误渲染、日志、axios 适配器和观测 SDK 映射为本地兼容实现，避免无意义的平台外部请求。
- 真实浏览器验收达到控制台 0 错误、失败请求 0 个、4xx/5xx 响应 0 个，并完成三个修复入口跳转检查。

## 6. 下一阶段建议

### P0：做到首次成功不需要查文档

1. 发行包内置 Node 运行时，避免要求普通用户安装 npm 环境。
2. 为 ffmpeg、yt-dlp、whisper-cli 提供受控依赖包或引导安装器，记录版本、许可证、下载源和校验值；不要静默修改系统环境。
3. 增加 Whisper 模型管理器：推荐模型、磁盘占用、下载进度、断点续传、校验和删除。
4. 增加自定义依赖路径与自动发现，解决命令已安装但不在 PATH 的问题。
5. 首次启动执行一次最小烟雾测试：创建测试任务、生成短文本、写入本地结果，再给出“可以开始”。
6. 把文件目录、剩余磁盘空间、端口和写权限纳入启动自检。
7. 建立正式的版本化数据库迁移机制，记录 schema 版本、升级顺序、失败回滚和旧数据兼容策略。

### P1：降低第三方配置难度

1. 外部模型增加提供商预设、基础 URL 自动填充、模型列表或示例、连接测试和错误归类。
2. 腾讯云 ASR 改为分步向导，并明确 COS 费用、地域一致性和最小权限。
3. 平台下载仅在真实失败后请求浏览器 Cookie，并记录上次成功浏览器。
4. 飞书和钉钉提供“最小权限清单”和授权回调状态，不让用户手工猜权限。
5. 增加脱敏诊断包，一键导出版本、能力状态和最近错误，不包含密钥与原始资料。

### P2：把配置变成场景模板

提供三个一键方案：

- 文档轻量版：本地输出 + 总结模型。
- 本地隐私版：本地输出 + ffmpeg + 本地 Whisper + 外部或本地兼容模型。
- 云端省资源版：本地输出 + ffmpeg + 腾讯云 ASR + 外部模型。

高级用户仍可逐项调整，普通用户只需选择方案并完成必要凭证。

## 8. 风险与回滚

- 自动下载二进制会引入许可证、供应链、校验、更新和管理员权限风险。本轮不实施静默系统安装。
- 云服务和外部模型可能产生费用，配置页必须在启用前说明计费主体和数据流向。
- 浏览器 Cookie、API Key、SecretKey 和 Webhook 密钥属于敏感信息，诊断与日志必须脱敏。
- Windows、macOS 的命令路径和权限模型不同，依赖发现与安装需要分别验证。
- 本轮前端改动可通过单个 Git 提交回滚；配置数据结构未改变，旧设置 URL 保持兼容。
- 当前隔离运行配置仍声明 `database.file=data/workbench.sqlite`，而 PGlite 工厂实际使用 `data/pgdata`；本轮为避免无提示切换已有数据未改变路径语义，后续应统一配置字段并提供显式迁移。
