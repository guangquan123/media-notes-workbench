# 录音笔记页面体验优化需求规格书

文档状态：需求评审稿

版本：v1.0

日期：2026-08-31

范围：录音笔记入口、麦克风检测、开始录音、录音中、录音完成确认、转化处理中

## 1. 需求概述

### 1.1 背景

当前录音页把用户要做的事情和系统内部可靠性信息放在同一层级。首屏同时展示录音标题、笔记风格、录音模式、语言模式、词表、三项可靠性说明、两段安全提示，以及右侧的质量保障、处理配置和后台运行提示。用户需要先阅读大量技术信息，才能找到“检测麦克风”和“开始录音”。

当前麦克风检测虽然会更新 `deviceState` 和音频指标，但用户可见反馈主要依赖按钮文案和 toast，缺少连续的、可理解的检测过程反馈。录音中页面也把分片数、写入字节数、采样等内部指标直接暴露给用户，造成信息噪声和大面积留白。

### 1.2 当前实现依据

- 页面首屏结构与两栏布局位于 [RecordingNotesPage.tsx](/D:/data/codex_space/media-notes-workbench/client/src/pages/RecordingNotesPage/RecordingNotesPage.tsx:653)。
- 设置页同时呈现高级参数、可靠性说明、安全提示和恢复存储信息，位于 [RecordingPanels.tsx](/D:/data/codex_space/media-notes-workbench/client/src/pages/RecordingNotesPage/RecordingPanels.tsx:113)。
- 录音中页直接展示设备、分片、文件大小、静音时长和恢复保护，位于 [RecordingPanels.tsx](/D:/data/codex_space/media-notes-workbench/client/src/pages/RecordingNotesPage/RecordingPanels.tsx:291)。
- 麦克风检测会将音频指标更新到 `inputDetected`、`rms`、`silentForMs`，检测逻辑位于 [reliable-recorder.ts](/D:/data/codex_space/media-notes-workbench/client/src/pages/RecordingNotesPage/reliable-recorder.ts:315)。

### 1.3 目标

1. 用户进入页面后 5 秒内能理解下一步，并在 1 次视线扫描内找到主要操作。
2. 用户能明确知道麦克风检测处于哪个阶段、是否有声音输入、为什么还不能开始录音。
3. 用户在录音过程中只看到与“录得是否正常”和“下一步如何操作”有关的信息。
4. 桌面端减少右侧重复信息和无意义留白；移动端不需要横向滚动，主要按钮始终可达。

### 1.4 非目标

- 本需求不改变录音文件格式、转录服务、上传流程、本地恢复机制和后端 API。
- 本需求不取消录音异常保护，只改变其展示层级和文案。
- 本需求不在本阶段新增音频编辑、多人协作或实时转写能力。

## 2. 用户与核心任务

### 2.1 目标用户

需要快速录下课堂、会议、访谈或语音备忘，并在录音后生成结构化笔记的普通业务用户。用户关心“能不能开始”“有没有录上”“什么时候可以拿到笔记”，不关心采样率、分片数量和具体转录模型。

### 2.2 主任务路径

`进入录音页 → 填写/确认标题 → （可选）选择笔记风格 → 测试麦克风 → 看到声音输入确认 → 开始录音 → 暂停/继续 → 完成录音 → 试听确认 → 转为笔记`

### 2.3 成功标准

- 主要路径中，用户无需打开设置或阅读技术说明即可完成录音。
- 麦克风测试成功前，“开始录音”不可用；不可用原因在页面内可见。
- 检测过程每个阶段都有状态文本和视觉反馈，不能只改变按钮文字或只弹 toast。
- 录音中出现静音、削波、设备断开或恢复存储异常时，用户在 1 秒内看到明确的异常提示和可执行动作。

## 3. 信息架构与布局

### 3.1 总体结构

采用单列任务流，桌面端内容最大宽度建议 760–840px，移动端使用 16px 内边距。页面高度由内容决定，不再用撑满视口的双栏卡片制造空白。

```text
顶部导航：返回入口                    当前步骤：准备 / 录音 / 确认
主内容：页面标题 + 当前任务表单
        麦克风检测模块
        主操作区
异常/恢复提示：仅在触发时出现
```

### 3.2 信息分层

| 层级 | 默认展示内容 | 处理方式 |
| --- | --- | --- |
| 必须可见 | 标题、笔记风格、麦克风检测状态、开始/完成录音按钮、计时器、声音输入反馈 | 首屏直接展示 |
| 有帮助但非必需 | 录音模式、语言模式、词表、自动保存说明 | 收进“高级设置（可选）”，默认折叠；保持当前值 |
| 系统诊断 | 采样率、声道、分片数、文件字节数、转录提供者、处理环境 | 默认不展示；出现异常或用户主动展开“查看详情”时展示 |
| 异常信息 | 权限拒绝、无设备、占用、静音、断开、恢复存储失败、长时间无声 | 立即以内联警告展示，必要时保留 toast 作为辅助通知 |

### 3.3 必须移出首屏的内容

- “录音质量保障”右侧独立卡片及其重复状态列表。
- “当前处理配置”右侧卡片；转录引擎、说话人分离和处理环境移入高级设置或处理结果详情。
- “开始前检查 / 录音中监控 / 意外可恢复”三张说明卡，改为麦克风检测模块下方的一行简短说明或帮助提示。
- “每秒写入分片”、采样参数、文件字节数和分片数等内部实现指标。
- 仅描述系统行为、但不帮助用户做当前决策的长段落。

## 4. 详细需求

### 4.1 页面壳层与步骤导航（P0）

**需求**

- 顶部仅保留产品名“实时录音笔记”、返回入口和当前步骤指示。
- 步骤指示固定为“准备 / 录音 / 确认”；当前步骤高亮，已完成步骤可识别，不能用大段说明代替。
- 桌面端不显示右侧固定信息栏；移动端不出现横向滚动。
- 页面主内容和操作区域采用 16/24px 间距体系，避免连续大块空白。

**验收**

- 1440px 宽度下主任务内容集中在页面中部，首屏不出现与任务无关的第二列卡片。
- 390px 宽度下标题、按钮和状态文本均不溢出，主要按钮宽度至少 44px 高。
- 进入页面后首屏能同时看到标题、麦克风检测入口和开始录音按钮。

### 4.2 准备页精简与高级设置（P0）

**默认可见**

1. 页面标题：`开始一段新录音`。
2. 录音标题输入框，保留当前自动生成标题。
3. 笔记风格选择器，保留“学习笔记 / 会议纪要”。
4. 麦克风检测模块。
5. 主按钮：检测成功后为“开始录音”；检测前显示禁用态并说明原因。

**高级设置**

- 折叠入口文案：`高级设置（录音模式、语言、词表）`。
- 展开后保留现有录音模式、语言模式和词表字段；关闭后不清空已填写值。
- 高级设置默认折叠状态不影响配置读取和提交。
- 转录引擎、说话人分离、处理环境不放在准备页主流程中；在高级设置中最多提供“沿用系统配置”的一句话和配置页链接。

**恢复录音**

- 检测到未完成录音时，在主操作区上方显示恢复横幅：录音时长、`恢复录音`、`丢弃`。
- 恢复操作优先级高于新录音；有恢复内容时新录音按钮禁用并说明原因。

**自动保存**

- 正常状态只显示紧凑标签：`自动保存已开启`。
- 存储不可用时显示阻断式错误：说明无法开始录音的原因，并提供“重试检查”；不展示底层存储名词。

### 4.3 麦克风检测动态反馈（P0）

麦克风检测必须以内联状态组件为唯一主反馈源，toast 只能作为辅助提醒。状态、文案、按钮和视觉反馈按下表实现：

| 状态 | 触发条件 | 用户看到的内容 | 操作 |
| --- | --- | --- | --- |
| 未检测 | 初始或重置后 | 灰色麦克风图标；`还没检测麦克风`；按钮 `检测麦克风` | 点击开始检测 |
| 请求权限 | 调用 `getUserMedia` 后等待 | 旋转图标/进度动效；`正在连接麦克风…`；按钮禁用 | 等待浏览器权限结果 |
| 已连接待说话 | 获得有效音轨但尚未超过声音阈值 | 绿色设备点；静态或低幅波形；`麦克风已连接，请说一句话测试`；显示音量条 | 用户说话 |
| 检测到声音 | 音量超过阈值并持续至少 500ms | 波形/音量条实时跳动；绿色勾；`声音已检测到，可以开始录音` | 启用 `开始录音` |
| 无声音超时 | 已连接后连续 8 秒没有有效输入 | 黄色提示；`还没检测到声音，请靠近麦克风并说话`；保留动态音量条 | 继续说话或 `重新检测` |
| 声音过低/不稳定 | 检测到输入但低于稳定阈值，或持续静音超过 12 秒 | 黄色提示；`声音偏小，建议靠近麦克风` | 用户调整位置；不强制中断 |
| 权限拒绝 | `NotAllowedError` | 红色错误；`麦克风权限未开启，请允许访问后重试` | `重新检测`；不只依赖 toast |
| 没有设备 | `NotFoundError` | 红色错误；`没有检测到可用麦克风` | `重新检测` |
| 设备占用 | `NotReadableError` | 红色错误；`麦克风正被其他程序占用，请关闭后重试` | `重新检测` |
| 设备静音/断开 | `onmute` / `onended` | 红色或黄色异常条；说明是否已暂停或自动保存；提供 `重新检测设备` 或 `完成并试听` | 执行动作 |

**动态反馈细则**

- 检测按钮点击后 100ms 内进入“请求权限”状态，避免用户认为点击无效。
- 音量条至少每 250ms 更新一次；同时提供文本状态，不能只用颜色或动画表达。
- 检测成功条件需要可解释：声音输入超过现有 `SIGNAL_RMS_THRESHOLD`，并连续保持至少 500ms。
- 检测过程中必须保持页面布局稳定，状态文本变化不能推动按钮上下跳动。
- `prefers-reduced-motion: reduce` 下取消或降低波形动画，但保留数值/文字状态。
- 状态容器使用 `aria-live="polite"`；权限和设备错误使用 `aria-live="assertive"`，避免重复播报同一状态。

### 4.4 开始录音页（P0）

**布局**

- 采用单一录音工作区，不显示准备页的表单、处理配置或系统诊断卡片。
- 顶部显示状态标签 `录音中` / `已暂停`、录音标题和计时器。
- 中部显示实时波形或音量条、当前声音状态和必要的异常提示。
- 底部只保留 `暂停`、`继续` 和主按钮 `完成录音`。

**默认可见信息**

- 已录时长。
- 声音状态：`声音正常`、`请说话`、`声音偏小`、`麦克风已静音`、`设备已断开`。
- 自动保存状态：正常时用短标签 `自动保存中`，异常时显示原因。

**默认隐藏信息**

- 分片数量、已写入字节数、采样率、声道、恢复存储技术说明。
- 这些信息仅在用户点击 `查看录音详情` 或发生保存异常时展示。

**异常与保护**

- 连续无声超过 12 秒显示非阻断提示，不自动停止录音；提示建议靠近麦克风或检查静音。
- 削波时显示 `声音过大，建议降低输入音量或移远麦克风`，不展示 `clipCount`。
- 系统静音时自动暂停必须在录音区域顶部显示，按钮切换为 `继续录音`，并说明恢复设备后可继续。
- 设备断开时立即显示已断开状态，并将“完成并试听”作为安全出口；禁止让用户误以为录音仍在采集。
- 恢复存储中断时立即显示阻断式提示，说明录音已暂停且当前内容仍可完成保存。

### 4.5 录音完成确认页（P1）

- 保留音频播放器和时长，标题改为 `录音已保存，先试听确认`。
- 主按钮为 `转为笔记`；次要操作为 `重新录音` 和 `下载备份`。
- 完整性检查默认展示一句结论；只有状态为 `需要确认` 或 `失败` 时展开具体原因。
- 隐藏分片数和内部文件大小；如确有诊断需要，放入“录音详情”。

### 4.6 转化处理中（P1）

- 默认只显示阶段进度、当前处理文案和百分比。
- 转录提供者、模型名称、处理环境作为“查看处理详情”折叠内容。
- 失败时保留录音，主操作为 `返回试听` 或 `重新提交`，避免用户丢失已录内容。

## 5. 交互与状态规则

### 5.1 状态转移

```text
未检测 → 请求权限 → 已连接待说话 → 检测到声音 → 可开始录音
                                  ↘ 无声音超时 → 重新检测/继续说话
可开始录音 → 录音中 ↔ 已暂停 → 录音完成 → 试听确认 → 转化处理中 → 完成/失败
```

- 修改录音模式或语言模式后，麦克风准备状态重置为“未检测”，避免旧设备状态与新配置不一致。
- 开始录音前必须同时满足：设备 ready、检测到声音、自动保存 ready、无待恢复录音。
- 点击完成录音后按钮进入 `正在保存`，在保存完成前不可重复点击。
- 页面刷新或意外中断后，恢复横幅优先显示，且不得静默覆盖。

### 5.2 按钮规则

- 每个状态最多一个主按钮；主按钮文案使用动作 + 结果，例如 `开始录音`、`完成录音`、`转为笔记`。
- 禁用按钮必须在同一模块显示禁用原因，不依赖 hover 或 toast。
- 不使用“检查”“处理”等无法体现结果的泛化文案作为唯一反馈。

## 6. 无障碍与响应式要求

- 所有状态不能只依赖红/黄/绿颜色，必须同时有文字和图标/形状。
- 录音计时器使用等宽数字并标注为动态区域；屏幕阅读器不应每 250ms 播报一次，建议仅在状态改变时播报。
- 按钮、输入框和折叠入口的可操作区域至少 44×44px，并有可见焦点态。
- 音量条提供文本替代，例如 `当前输入音量 42%，声音正常`。
- 390px、768px、1440px 三档视口均需验证，不出现横向滚动、文字截断或按钮遮挡。

## 7. 埋点与可观测性（P1）

建议记录以下事件，不记录原始音频或敏感内容：

- `recording_mic_test_started`
- `recording_mic_permission_result`（允许/拒绝/无设备/占用）
- `recording_mic_signal_detected`
- `recording_started`
- `recording_paused` / `recording_resumed`
- `recording_device_interrupted`
- `recording_saved`
- `recording_convert_submitted` / `recording_convert_failed`

关键指标：检测成功率、从进入页面到开始录音的中位时长、检测后放弃率、设备异常率、录音完成率、试听后转化率。

## 8. 验收标准

### 8.1 功能验收

- 首屏不展示右侧质量保障、处理配置和长段系统说明。
- 高级设置默认折叠，展开/收起不丢失用户已填写值。
- 检测按钮点击后立即出现进行中状态；获得音轨后出现“请说话”状态；检测到声音后出现绿色确认并启用开始录音。
- 权限拒绝、无设备、设备占用、设备静音、设备断开和长时间无声均有页面内明确反馈与下一步动作。
- 开始录音前未通过声音检测时，按钮保持禁用且原因可见。
- 录音中只显示时长、声音状态、自动保存状态和必要异常；完成/暂停按钮行为与现有录音保护一致。
- 录音完成后仍可试听、重新录音、下载备份和转为笔记。

### 8.2 视觉与布局验收

- 桌面端主内容为单列任务流，首屏主要操作位于同一视口内。
- 页面不因状态文案长度变化产生明显跳动。
- 移动端按钮不被底部浏览器区域或内容遮挡，操作顺序清晰。
- 视觉层级只有一个主标题和一个主操作，不再同时出现多个高权重卡片标题。

### 8.3 可访问性验收

- 键盘可完成检测、展开高级设置、开始/暂停/完成录音和试听确认。
- 状态变化可被屏幕阅读器感知，计时器不会高频打断阅读。
- 在减少动效设置下仍能理解检测是否成功。

## 9. 影响、兼容性与回滚

- 影响模块：录音页信息架构、展示组件和交互文案；录音采集、上传、转录和本地存储逻辑保持不变。
- API 影响：无新增或修改 API。
- 数据结构影响：无新增持久化字段；埋点若实施，沿用现有事件上报方式。
- 向后兼容：保留现有 `RecordingPhase`、录音保护和异常处理语义，仅调整视图映射和信息可见性。
