# 高质量笔记总结引擎 V3 保真方案

## 1. 目标

V3 解决 V2 只能检查“来源块和证据类型是否出现”，但无法证明每条事实被正确承载的问题。目标是同时获得：

- 接近人工参考稿的事实密度、案例细节和复用价值；
- 数字主体、单位、限定词和比较方向不变；
- 不把含糊转写升级为确定事实；
- 原始视觉素材存在时完整保留，纯文本输入不伪造图片；
- 每个阶段都有输入、输出和通过条件。

## 2. 流水线

```text
原始材料
  ↓ 无损分块
JSONL 结构化证据账本
  ├── 稳定证据 ID
  ├── 来源、类型、说话人和时间戳
  ├── certainty / ASR 风险
  └── 数字主体、值、单位和比较运算符
  ↓ 独立逐句比较原文与账本
证据缺口审计
  ├── 只补充真正遗漏的信息
  ├── 每条补充证据携带逐字原文引用
  └── 程序验证引用确实存在于当前原文分块
  ↓ 即使两次模型提取同时漏项
本地高信息密度原文锚点
  ├── 确定性保留数字、操作步骤、风险、限制和案例
  ├── 保留逐字原话、时间戳和说话人，不猜改 ASR 文本
  └── 阿拉伯数字额外记录比较方向
  ↓
逐证据覆盖计划
  ↓ 系统确定性补齐模型漏掉的证据 ID
详细主笔记
  ↓
程序质量门禁 + 独立事实审校
  ├── 逐证据覆盖
  ├── 数字方向和主体
  ├── 无来源新增事实
  ├── 不确定性处理
  ├── 原始图片覆盖
  └── 结构、密度和可读性
  ↓ 不通过，最多定向修订两次，每次重新审校
最佳候选稿
  ↓ 内部证据 ID 转为来源标记
发布稿
```

## 3. 结构化证据

每行证据使用 JSON Lines，示例：

```json
{
  "id": "E-S01-001",
  "sourceId": "S01",
  "type": "数字",
  "statement": "知识图谱在 3.5 以上模型版本中可能无法生成。",
  "certainty": "direct",
  "asrRisk": "low",
  "numericClaims": [
    { "subject": "知识图谱模型版本", "value": "3.5", "operator": "gte" }
  ]
}
```

证据 ID 在分块内稳定递增。合并账本时不得删除或改写 ID；压缩后若缺少任一 ID、来源、类型或数字，整轮压缩作废并保留原账本。旧版 `[S01][事实]` 账本继续兼容，但不具备逐条 ID 门禁。

首次提取后，每个原文分块都会经过一次独立缺口审计。审计只允许输出遗漏证据或 `NO_MISSING_EVIDENCE`。补充证据必须携带从当前分块逐字复制的最短 `quote`；引用缺失、不可解析或不在原文中时直接失败，不能把审计异常降级为“没有遗漏”。

缺口审计完成后，系统还会在本地扫描原文，确定性补入数字、操作、风险、限制和案例等高信息密度片段。该步骤不调用模型，不把整篇原文回填到账本，也不把 `topic k`、`0..9%` 等疑似 ASR 文本擅自纠正为确定事实；规范化表达仍需由写作阶段生成并接受事实审校。已有逐字引用不会重复加入。

## 4. 覆盖与审校

写作前必须为每条证据指定正文落点。规划模型遗漏的条目由系统把原始陈述补入计划，避免二次模型调用仍然漏项。

草稿完成后执行两类检查：

1. 程序门禁检查源文本引用、结构、证据 ID、来源、数字集合、比较方向、正文密度、原始图片和可追溯性。
2. 独立事实审校比较证据账本与草稿，检查遗漏、矛盾、无来源事实和不确定性升级。

两类检查的失败原因合并后交给修订模型。系统保留初稿和每次修订稿，按“门禁通过、质量分、审校问题数”选择最佳候选，不再把最后一次修订天然视为最好。

## 5. 视觉保真

- 视频帧优先使用图像识别文本、摘要和图表描述匹配笔记章节；没有足够语义信号时才按时间轴分配。
- 文档解析结果中的 Markdown 原图如果被模型遗漏，系统按图片 alt 文本匹配章节并确定性补回；无法匹配时进入“一页复习”之前的“原始资料图片”。
- 派生信息图只能作为补充，原始截图始终保留在上方。
- `.txt` 等纯文本输入没有图片资产，系统不得生成替代图片冒充原材料。要复现带截图的参考稿，必须上传原视频或包含图片的文档。

## 6. 验收阈值

真实长培训样本采用以下门槛：

| 维度                 | 通过条件              |
| -------------------- | --------------------- |
| 高优先级事实         | 100% 命中             |
| 全部中高价值证据     | 至少 95% 命中         |
| 数字主体、单位、方向 | 100% 正确             |
| 事实矛盾             | 0                     |
| 无来源新增事实       | 0                     |
| 不确定性标记         | 100% 正确             |
| 原始视觉素材         | 输入存在时 100% 保留  |
| 有效正文长度         | 人工参考稿的 90%–115% |

`scripts/run-note-fidelity-regression.ts` 可在本地生成候选稿并输出机器可读报告，也可以传入第五个候选稿参数执行离线评估：

```bash
npx ts-node --project tsconfig.node.json scripts/run-note-fidelity-regression.ts \
  source.md reference.md expectations.json candidate-output.md [existing-candidate.md] [--builtin]
```

报告同时输出本地原文锚点的数量、字符数、原文占比和证据类型分布，用于监测兜底规则是否过窄或接近整篇复制；这些诊断指标不替代成稿事实、禁错项和长度门禁。

真实原文发送到外部模型前必须得到用户明确授权。回归脚本只写本地候选稿，不发布或修改飞书文档。

## 7. 缓存与兼容

V3 使用新的引擎版本参与证据缓存键，旧版证据缓存不会复用。API 和数据库结构不变；发布稿仍显示 `[S01]` 等来源标记，内部证据 ID 不暴露给最终读者。
