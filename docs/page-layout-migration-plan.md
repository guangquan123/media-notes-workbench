# 页面布局迁移实施方案与交付验收

版本：1.0
范围：任务页、设置页、数据页的无效滚动与大面积空白治理
原则：布局迁移不改变业务状态、接口、数据结构或既有路由

## 1. 目标与非目标

目标是消除内容少却因固定最小高度、嵌套全屏容器和编辑器自动增高造成的无效滚动，确保核心输入、状态和主 CTA 在桌面首屏可用，并保持移动端自然滚动。

非目标包括：重做视觉品牌、全局色彩迁移、改造后端 API、重写任务状态机、改变录音文件生命周期，以及一次性迁移所有历史页面。

## 2. 根因与优先级

| 根因 | 典型位置 | 处理优先级 |
| --- | --- | --- |
| 固定 `min-height` 把卡片撑高 | 入口页主卡片、任务结果面板 | P0 |
| 页面与嵌入组件重复使用 `main`、`min-h-screen` | 设置页、模型/转写/模板/连接器 | P0 |
| 长文本编辑器按内容自动增高 | 提示词模板编辑器 | P0 |
| 页面滚动和面板滚动没有明确归属 | 视频、音频、文档任务页 | P1 |
| 历史和数据页面真实内容较长 | 转换历史、录音库、手册 | P2，保留自然滚动 |

## 3. 实施分层

### 3.1 页面契约

- 任务页使用 `page-layout--task`，桌面端固定视口工作区，只有任务面板内部滚动；移动端恢复自然滚动。
- 设置页使用 `page-layout--settings`，保留页面自然滚动；长编辑器拥有独立高度上限。
- 数据页使用 `page-layout--data`，保留自然滚动，不因压缩而截断数据。
- `Layout` 仍负责运行时健康检查和启动器就绪上报，不纳入本次布局迁移。

### 3.2 当前批次

| 模块 | 变更 | 业务影响 |
| --- | --- | --- |
| `MediaNotePage` | 接入任务页契约，降低无内容状态的最小高度 | 覆盖视频、本地视频、音频、文档入口；上传/轮询逻辑不变 |
| `HomePage` | 接入任务页契约，入口卡片改为内容驱动高度 | 入口与任务创建 CTA 行为不变 |
| `SettingsPage` | 标记设置页契约 | URL 查询参数与分区导航不变 |
| 模板、AI、转写、连接器设置 | 嵌入时使用 `section`，独立访问仍使用 `main` | API、保存、发布、测试连接不变 |
| 提示词编辑器 | 增加视口相关最大高度与内部滚动 | 内容、保存、发布、版本比较不变 |

### 3.3 后续批次

配对媒体、录音任务、录音库/播放器、转换历史和操作手册分别迁移。录音相关文件当前存在未提交改动，必须先单独稳定和回归，再进行布局接入。

## 4. 稳定性控制

1. 不修改后端、共享 API、数据库和任务状态机。
2. 不移动业务 Hook，不改变 React key，不改变上传取消、轮询和保存发布的调用顺序。
3. 不在全局外壳添加 `overflow: hidden`；只在桌面任务页的明确工作区使用。
4. 每个批次单独提交，发现回归时用 `git revert` 回退该批次。
5. 对已有未提交文件不做覆盖式整理；迁移提交只包含明确的布局文件与测试文件。

## 5. 测试用例

### 5.1 自动化契约测试

- `page-layout-migration.spec.ts`：检查布局契约存在、入口卡片不再使用固定高度、任务页桌面/移动滚动规则存在、编辑器有高度上限、嵌入设置组件不产生嵌套 `main`。
- 客户端类型检查：`npm.cmd run type:check:client`。
- 前端构建：`npm.cmd run build:client:local`。

### 5.2 功能回归

| 用例 | 预期 |
| --- | --- |
| 视频链接为空提交 | 保留原提示，不发起任务 |
| 视频链接正常提交 | 创建任务并继续轮询，完成后可打开笔记 |
| 本地视频/音频/文档选择与移除 | 文件列表、大小、移除行为正常 |
| 上传中取消 | 上传停止，页面可再次选择文件 |
| 任务处理中取消 | 状态变为取消，页面不死锁 |
| 任务失败重试 | 原输入保留，重试按钮可用 |
| 设置分区刷新 | `section` 查询参数保留，分区正确选中 |
| 提示词编辑、保存、发布 | 未保存、保存中、成功、失败状态正确 |
| 版本选择与比较 | 最多两个版本，返回路径保持 |
| 模型/转写/连接器测试 | 连接测试、保存和错误提示不受布局影响 |
| 录音库行操作与播放 | 行选择、播放和键盘操作保持可用 |

### 5.3 视觉与易用性回归

视口：1280x720、1366x768、360x800；检查首屏、滚动条数量、CTA 可见性、文本溢出、空白面积和错误提示位置。

通过条件：

- 任务页必要输入和主 CTA 在桌面首屏同时可见。
- 桌面任务页最多一个任务面板滚动容器；移动端无嵌套滚动。
- 设置页的长编辑器不把保存操作推到数屏之外。
- 空数据、加载、失败、取消和成功状态均有清晰内容，不使用整页空白代替。
- 每页只有一个顶层 `main`；图标按钮有可读名称，键盘可达。

## 6. 验证与交付门槛

交付前必须依次完成：契约测试、客户端类型检查、前端构建、完整 Jest 测试、开发服务健康检查、三组视口人工回归、git diff 检查。

任何一项失败都不标记为完成；若失败来自现有未提交改动或环境限制，必须在交付报告中明确区分，不能归因于本次布局变更。
