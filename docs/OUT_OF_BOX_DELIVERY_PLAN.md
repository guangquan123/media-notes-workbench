# 客户开箱即用与稳定交付实施方案

版本：v2.0
日期：2026-09-14
适用版本基线：2.2.5；本方案为下一版客户交付基线

## 1. 交付结论与目标

当前版本适合技术型客户试用，不适合直接对普通客户承诺“下载安装后立即生成结果”。本方案的目标是把产品提升到以下交付标准：

- 客户只下载并安装一个 Windows 安装包，不需要安装 Node.js、npm、ffmpeg 或 yt-dlp；模型一律通过外部服务使用，不随包分发。
- 首次启动只回答“我要处理什么资料”，系统只显示该场景所需配置。
- 在没有任何可选服务时，文档处理和本地保存仍有一条可验证的最短成功路径。
- 启动失败、依赖缺失、网络失败、模型失败、磁盘不足和端口冲突都能被识别、解释、修复或安全退出。
- 任务不会因为服务重启而静默丢失；失败可以从明确阶段重试。
- 发布前能在干净 Windows 10/11 x64 虚拟机完成安装、首次使用、升级、恢复和卸载验收。

非目标：本阶段不做多人 SaaS 化、不做自动向微信公众号/知乎/抖音发布、不绕过第三方登录或平台限制。

## 2. 六个 P0 工作流

| 编号 | 工作流 | 解决的客户问题 | 交付结果 |
| --- | --- | --- | --- |
| P0-1 | 真正的发行包与运行时 | 客户没有 Node/npm 也能启动 | 内置 Node、启动器自检、单实例、可诊断日志 |
| P0-2 | 媒体依赖与外部模型配置 | 客户不知道去哪装 ffmpeg/yt-dlp，也不清楚模型数据流向 | 受控媒体工具、外部模型向导、连接测试、费用/隐私提示 |
| P0-3 | 首次启动向导与最小烟测 | 客户打开后不知道先配什么 | 场景选择、最小配置、连接测试、端到端烟测 |
| P0-4 | 统一自检、修复与稳定启动 | 页面打开但后台失联、端口冲突、依赖失败 | capability readiness、自动修复、明确状态、幂等启动 |
| P0-5 | 正式数据库迁移与任务恢复 | 升级/重启导致任务丢失或 schema 不一致 | 版本化迁移、锁、备份、恢复、持久化 job |
| P0-6 | 外部模型与连接器降门槛 | API、飞书/钉钉配置复杂且失败难排查 | 场景模板、分步向导、脱敏诊断、失败不切换 |

## 3. 总体产品原则

### 3.1 场景优先，依赖后置

首次使用先选择：

1. 文档笔记；
2. 本地音视频；
3. 平台视频链接；
4. 同步到飞书/钉钉。

系统根据选择生成最小配置清单。未选择的能力显示“稍后启用”，不得显示为阻塞项。

### 3.1.1 模型外部化的取舍

| 选择 | 得到 | 牺牲 | 产品补偿 |
| --- | --- | --- | --- |
| 模型全部外部 | 安装包更小；无模型许可证和大文件分发；模型可独立升级；硬件要求更低 | 依赖网络/服务商；可能产生 API 费用；敏感原文可能离开本机 | 首次配置向导、数据流向确认、费用提示、连通性测试、长文本超时分类、可切换提供商 |
| 媒体工具随包 | 本地音视频和平台下载无需另装工具；减少 PATH 和版本问题 | 安装包变大；需维护 Windows 二进制和许可证 | 固定版本 + SHA-256 + 许可证清单；不修改系统 PATH；工具独立更新 |
| 不携带模型权重/本地推理 | 避免 50MB-数 GB 模型包、下载断点和显卡兼容问题 | 无离线转录/总结 | 未配置外部模型时仍可安装、自检、浏览历史；生成入口清楚显示阻塞原因 |

### 3.2 默认可用，失败可解释

- 默认输出使用本地连接器。
- 默认通知关闭。
- 默认不读取浏览器 Cookie；只有平台下载真实失败时才提示选择已登录浏览器。
- 模型统一走外部服务（OpenAI 兼容、DeepSeek、Ollama 远程端点或腾讯云 ASR）；安装包不内置模型权重、Whisper 模型或本地推理运行时。
- 外部模型未配置时允许安装、打开、浏览历史和运行本地烟测，但对需要生成内容的入口明确显示“配置外部模型后可用”，不得伪装成可生成。
- 每个失败必须包含：失败对象、当前阶段、是否已产生费用、下一步动作、重试是否安全。
- 不允许“页面看起来成功但任务实际失败”。

### 3.3 任何破坏性动作都可恢复

- 依赖升级前保留旧版本和校验信息。
- 数据库迁移前自动备份；迁移失败保留旧数据并阻止继续写入。
- 卸载默认不删除 `%LOCALAPPDATA%\\MediaNotesWorkbench` 用户数据。
- 任务重试使用幂等键，避免重复创建文档或重复扣费。

## 4. 目标架构

```text
Windows Setup.exe
  ├─ embedded Node runtime
  ├─ app/dist/server + client + shared
  ├─ controlled-tools/ffmpeg, yt-dlp
  ├─ tool-manifests/*.json
  └─ launcher/health-check/repair/logs

%LOCALAPPDATA%\\MediaNotesWorkbench
  ├─ data/       # PGlite、notes、uploads、recordings、jobs
  ├─ config/     # provider、connector、tool paths、consent
  ├─ cache/      # 下载缓存、可清理临时文件
  ├─ logs/       # launcher、server、client、audit
  └─ runtime/    # pid、lock、migration marker、health snapshot
```

后端新增统一能力模型，前端只消费一个聚合接口：

```ts
interface CapabilityReadiness {
  capability: 'documents' | 'local_media' | 'platform_media' | 'external_sync';
  status: 'ready' | 'action' | 'optional' | 'error';
  blockers: ReadinessBlocker[];
  action?: ReadinessAction;
  checkedAt: string;
  version: string;
}
```

所有服务端接口继续使用 `/api` 前缀，所有写接口显式使用 `@NeedLogin()`（local runtime 由本地身份适配）。共享类型必须先写入 `shared/api.interface.ts`，再实现 Controller、Service 和前端 API。

### 4.1 外部模型状态机（正式契约）

外部模型按“配置记录”和“可用性探测”分离建模。保存配置不会直接把能力标记为可用，只有一次成功的探测请求才能进入 `ready`。

| 状态 | 含义 | 可接受动作 | 自动转移 |
| --- | --- | --- | --- |
| `unconfigured` | 没有完整配置 | 新增/导入模板 | 保存草稿后进入 `configured` |
| `configured` | 配置已保存但未验证 | 测试连接、编辑 | 测试开始进入 `testing` |
| `testing` | 正在执行短请求和能力检查 | 取消 | 成功进入 `ready`；失败进入 `error` |
| `ready` | 最近一次探测成功且未过期 | 使用、重新测试、停用 | 连续超时进入 `degraded`；主动停用进入 `disabled` |
| `degraded` | 可达性或额度不稳定 | 重试、切换备用提供商 | 探测成功回 `ready`；达到失败阈值进 `error` |
| `disabled` | 用户主动关闭 | 启用并测试 | 启用后进入 `configured` |
| `error` | 配置、鉴权、协议或内容限制错误 | 修复字段、查看原因 | 修改配置回 `configured` |
| `expired` | Key、临时授权或模型版本已失效 | 更新凭据/模型 | 更新后进入 `configured` |

状态转移必须写入 `model_provider_events`，包含 `providerId`、`from`、`to`、`reasonCode`、`runId`、时间戳和 `consentId`。禁止仅依赖内存状态。`ready` 的有效期默认为 15 分钟；执行长任务前必须重新确认，探测超时 10 秒、最多 2 次且采用 1/3 秒退避。错误码固定为 `CONFIG_INVALID`、`AUTH_FAILED`、`RATE_LIMITED`、`QUOTA_EXCEEDED`、`NETWORK_TIMEOUT`、`PROVIDER_5XX`、`CONTENT_REJECTED`、`MODEL_NOT_FOUND`、`CONSENT_REQUIRED`，前端按错误码展示唯一下一步。

配置对象只保存 `providerType`、`baseUrl`、`model`、能力（`summary`/`transcription`）、超时和非敏感元数据；密钥通过 Windows DPAPI/Credential Manager 保存，数据库只存引用。发送任何原文、音频或下载 URL 前，必须展示提供商、数据类别、预计费用等级和保留策略，并产生可撤销的 `consentId`。未同意时状态为 `configured`，任务不得发出外部请求。

### 4.2 资料类型依赖矩阵（readiness 与验收共用）

| 资料类型/动作 | 本地存储 | `ffmpeg` | `yt-dlp` | 外部转录 | 外部总结 | 外部同步 |
| --- | --- | --- | --- | --- | --- | --- |
| 文档导入/文本笔记 | 必需 | 不需要 | 不需要 | 不需要 | 生成时需要 | 可选 |
| 本地音频/视频 | 必需 | 必需 | 不需要 | 必需 | 必需 | 可选 |
| 平台视频 URL | 必需 | 必需 | 必需 | 必需 | 必需 | 可选 |
| 查看历史/导出本地文件 | 必需 | 不需要 | 不需要 | 不需要 | 不需要 | 不需要 |
| 运行本地烟测 | 必需 | 不需要 | 不需要 | 不需要 | 不需要 | 不需要 |

readiness 必须按行计算，不允许用“总开关”掩盖局部缺失。例如只有 `platform_media` 显示 `action` 时，文档和历史入口仍为 `ready`。每行依赖的版本、路径、状态和最近检查时间都要返回，作为向导、任务创建前校验和验收报告的唯一数据源。

### 4.3 launcher/server/client 动态端口握手

1. launcher 创建 `%LOCALAPPDATA%\\MediaNotesWorkbench\\runtime\\startup-{startupId}.json.tmp`，分配并探测 `serverPort`、`clientPort`，写入 launcher PID、版本、随机 `startupToken` 和创建时间，然后原子重命名为 `startup.json`。
2. server 启动时只接受命令行传入的 `serverPort` 和一次性 `startupToken`，监听成功后写入 `serverReadyAt` 和健康检查地址 `/api/runtime/handshake`。token 不写日志、不出现在 URL。
3. client dev/prod 代理读取同一 `startup.json`，将 `/api` 转发到 `serverPort`；浏览器入口使用 `clientPort`。前端轮询 handshake，连续 3 次失败才显示断联。
4. 重启先读取未过期（5 分钟）的 `startup.json`；端口仍由本实例占用且 token 匹配时复用，否则重新分配。端口冲突探测只验证监听者 PID/进程路径属于本产品，绝不结束未知 PID。
5. launcher 在 server、client、readiness 全部成功后才打开浏览器；任一失败写入 `startupFailure`，保留现场文件和诊断编号。退出时删除临时文件，保留最近 5 个已完成握手摘要。

握手协议的自动化测试必须覆盖：默认端口可用、server/client 各自冲突、启动中强制关闭、旧状态文件、未知进程占用和双实例竞争。

## 5. 分阶段实施

### 阶段 0：基线冻结与可观测性（1 周）

目标：让后续每个修复都有证据，不再依赖“页面能打开”。

- 固定发布版本、Node、媒体工具 manifest 和外部模型提供商配置格式。
- 为 launcher、server、client 写入统一 `runId`、`startupId`、`jobId`。
- 统一日志字段：阶段、能力、错误分类、重试次数、是否可恢复；禁止记录 API Key、Cookie、原文和完整 URL 查询参数。
- 增加 `health snapshot`，记录最近一次启动、迁移、自检和失败原因。
- 补充 article-export、启动器、迁移和依赖发现的测试基线。

退出标准：同一次启动可以从日志还原“为什么没就绪”，且脱敏抽查通过。

### 阶段 1：发行包与工具运行时（2 周）

#### P0-1 实施项

- `scripts/package-windows.js`：把受控工具、manifest、许可证和 SHA-256 清单纳入发布输入。
- `scripts/installed-launcher.js`：只启动已验证的 server/client，增加单实例锁和端口自动选择策略。
- `server/common/utils/tool-runtime-paths.ts`：统一解析内置工具、用户自定义路径和 PATH 的优先级。
- `scripts/workbench-launcher.hta`：把“正在启动/正在修复/已就绪/需要操作/失败”做成可读状态，不要求用户打开终端。
- 安装器：增加架构检查、磁盘空间检查、升级保留用户目录、卸载保留数据的明确文案。

端口策略：默认端口可用时复用；被非本项目进程占用时，在受控范围内选择空闲端口并写入运行时状态；禁止静默覆盖其他进程。具体握手协议见 4.3。

退出标准：干净机器没有 Node/npm 时，点击桌面图标后 60 秒内打开可交互页面；启动失败可看到具体修复动作。

### 阶段 2：媒体依赖和外部模型配置（2 周）

#### P0-2 实施项

- 建立 `tool-manifest.json`：名称、版本、来源、许可证、SHA-256、平台架构、安装目录、最小支持版本；只管理 ffmpeg、yt-dlp 等媒体工具。
- 发布包携带经过审核的 ffmpeg 和 yt-dlp；whisper-cli、Whisper 权重和其他模型运行时不进入安装包。
- 外部模型配置页提供提供商模板、Base URL、模型名、API Key、能力类型（总结/转录）、超时和数据流向说明。
- 支持“远程 OpenAI 兼容 API”和“腾讯云 ASR”两类转录方式；保存与测试分离，测试成功后才允许启用。
- 现有 `server/modules/note-jobs/note-jobs.service.ts` 中的本地 Whisper 分支标记为 deprecated：默认 feature flag 关闭，新建任务只能选择外部转录；旧历史任务可在兼容开关下完成迁移，迁移窗口结束后移除。
- 工具发现结果持久化为路径和版本，不只依赖当前进程 PATH；用户自定义工具路径必须经过版本/可执行性检查。
- 本地音视频入口在缺外部转录配置时显示“配置外部转录服务”，不显示不可操作的禁用按钮。
- 不提供模型下载、模型删除、模型磁盘占用和本地模型切换功能，避免把不交付的能力暴露给用户。

退出标准：新机器选择“本地音视频”后，媒体工具可直接使用，用户只需配置并测试一个外部转录服务和一个外部总结服务；任何外部服务失败都有明确恢复路径。

### 阶段 3：首次启动向导和最小成功路径（2 周）

#### P0-3 实施项

- 新增 `SetupWizard`，内部节点固定为：选择用途 → 检查环境 → 配置最小模型 → 配置输出 → 端到端烟测 → 完成；“完成”是结果页，不计为用户操作，首次必做路径不超过 5 次点击/提交。
- 文档场景默认不要求 ffmpeg、yt-dlp 或转录服务；本地音视频场景要求媒体处理工具和外部转录服务；平台视频额外要求 yt-dlp。
- 提供本地样例文本烟测（不调用模型）验证数据库、任务和输出链路；提供“外部模型连通性测试”验证真实生成能力，明确提示可能产生费用。
- 每一步支持“稍后处理”时必须标明会影响哪些入口。
- 完成页显示可用入口，而不是只显示“配置成功”。

烟测必须验证：目录可写、数据库读写、任务创建、阶段推进、结果持久化、重启后读取、临时文件清理。外部模型测试必须验证 API 地址、鉴权、模型能力和超时分类，不把本地烟测结果当成模型可用证明。

退出标准：新客户不看 README，只按向导完成文档场景并得到本地笔记；失败时能定位到一个配置项。

### 阶段 4：统一自检、修复和稳定启动（2 周）

#### P0-4 实施项

- 将 `GET /api/runtime`、`GET /api/note-jobs/readiness`、连接器、模型、存储状态聚合为 `GET /api/setup/readiness`。
- readiness 区分 `ready/action/optional/error`，可选能力失败不让整页空白。
- 启动器等待“页面资源、runtime、readiness”三者都通过后再打开浏览器。
- 页面断联时自动短轮询恢复；只有连续失败达到阈值才显示警告。
- 提供“重新检测”“修复本机环境”“查看脱敏日志”“复制诊断编号”四个动作。
- 后台任务启动前再次校验能力，避免 readiness 过期导致中途失败。
- 修复 `note_inbox` 等非核心后台任务：隔离失败、退避重试、不会污染主 readiness。

退出标准：端口冲突、后台启动慢、前端资源失败、可选模块异常、数据库初始化失败均有确定性状态和测试覆盖。

### 阶段 5：数据库迁移与任务恢复（3 周）

#### P0-5 实施项

- 建立 `schema_meta`/migration ledger：数据库类型、版本号、迁移名、校验和、执行时间、结果、错误信息和操作者。
- **local PGlite**：启动时用文件锁获取迁移租约；迁移前复制数据目录、`config`（不含密钥明文）和 manifest，保留最近 3 个恢复点。迁移失败立即切换只读，禁止自动在原目录反复写入；恢复在临时目录验证通过后再原子替换。
- **platform Postgres**：使用数据库 advisory lock + ledger 表执行同一版本序列；迁移前由平台备份策略生成可验证快照，应用只记录 snapshotId，不自行复制生产数据。应用检测到版本落后、未知版本或校验和漂移时进入只读并阻止新任务。
- 两套数据库使用同一 `schema-contract.json` 生成迁移清单；CI 对 PGlite 和 Postgres 各跑一遍迁移、回滚/重放和约束校验，禁止“本地通过、平台失败”的漂移。
- 将 `jobs`、`job_steps`、`artifacts`、`retry_attempts`、`outbox_events` 持久化，替换服务进程内存 `Map` 作为唯一状态源。
- 每个 job step 记录输入指纹、开始/结束时间、状态、错误分类、幂等键、外部请求 ID 和副作用状态；敏感 payload 只存哈希和引用。
- worker 领取任务时写入 `leaseOwner`、`leaseExpiresAt`，每 10 秒 heartbeat；lease 超过 60 秒未续租即标记 stale，由单一 reconciler 回收。单机最大并发默认为 CPU 核数的 1/2，上限 4，可在设置中降低。
- 阶段超时：下载 30 分钟、转录 60 分钟、总结 20 分钟、同步 10 分钟；超时最多重试 2 次。外部副作用前先写 outbox，完成后以提供商 request/idempotency key 对账；对账未知时暂停并要求人工确认，不盲目重发。
- 重启恢复协议：读取 `running`/`leased` job → 校验输入文件和配置版本 → 自动恢复纯本地、无副作用阶段；涉及外部写入或费用的阶段进入 `awaiting_recovery_confirmation`，界面显示上次 checkpoint、可能费用和“继续/放弃”两个动作。
- 文档创建、连接器写入和通知发送使用稳定幂等键（`jobId:stepId:operation`），连接器返回成功后才标记 outbox 完成；重复响应必须被识别为同一副作用。

退出标准：两套数据库迁移可重复执行且 ledger 一致；迁移中断后只读保护和恢复可验证；服务重启后任务历史和可恢复任务仍可查询；故障注入证明不会重复扣费或重复创建文档。

### 阶段 6：模型与连接器配置降门槛（1 周）

#### P0-6 实施项

- 外部模型提供商模板：DeepSeek、OpenAI 兼容、Ollama；自动填充 Base URL、模型示例和能力说明。
- API Key 只显示“已配置/未配置”，留空表示保留旧值；保存与测试连接分离。
- 配置测试分为短请求、长文本风险提示和余额/额度查询，不把短请求成功误报为长任务稳定。
- 飞书/钉钉连接器分步完成：授权 → 读取权限 → 写入测试 → 设为当前输出；测试失败不得切换当前连接器。
- 默认本地输出永远可用：结果写入 `%LOCALAPPDATA%\\MediaNotesWorkbench\\data\\exports`，同时在数据库保存相对路径、格式和校验和；外部同步失败不阻塞本地笔记生成。
- 历史页以本地结果为准，`outbox_events` 仅展示待同步/已同步状态；重新安装后先校验本地文件哈希，再允许继续同步。
- 增加脱敏诊断包：版本、能力状态、最近错误、工具版本、启动阶段；不含密钥、Cookie、原文、音频和完整请求体。

退出标准：普通客户只需选择一个模板并完成一次测试；错误页面能说明是地址、权限、额度、网络还是内容限制。

### 6.1 Windows 安全存储与数据外发边界

- API Key、腾讯云 Secret、连接器 refresh token 使用 Windows DPAPI（CurrentUser）或 Credential Manager；`config/providers.json` 只保存 credential reference、提供商和模型元数据。导出配置、备份和卸载均不包含可解密密钥。
- 日志采用字段级脱敏：`apiKey`、`authorization`、Cookie、token、请求体、音频路径中的用户名全部替换为固定掩码；Base URL 仅保留 origin，查询参数一律删除。异常栈不得包含原文片段。
- 外部请求前的确认页显示：资料类型（文档/音频/视频/URL）、提供商、区域、预计费用等级、是否保留输入和撤销入口。用户同意记录 `consentId`、策略版本、范围、时间和撤销时间；策略变化需重新同意。
- 默认不读取浏览器 Cookie、不上传本地文件到非用户选择的提供商。平台下载失败时仅引导用户显式选择浏览器会话，Cookie 只在内存中使用，任务结束立即清除。
- “导出诊断包”只允许包含版本、平台、依赖版本、readiness、错误码、runId/jobId 和时间线；打包前执行敏感字段扫描，发现原文、音频、Cookie、完整 URL 或密钥即拒绝导出并提示。
- 本地结果是事实来源：同步失败不回滚本地文件；outbox 保留待同步记录，用户可在历史页单独重试或删除同步任务。

### 6.2 发布包与供应链预算

- 安装包预算：压缩后不超过 250 MB；其中内置 Node、ffmpeg、yt-dlp 分别设上限并在 CI 中硬失败。模型权重、whisper-cli、本地推理运行时明确禁止进入包体。
- 每个二进制记录上游 URL、版本、许可证、SHA-256、构建日期、目标架构和维护人；构建机只允许从锁定来源下载，验签/哈希失败不得产包。
- Windows 安装器和 launcher 使用组织代码签名；签名证书过期、时间戳失败或 Defender 扫描出现高危项时阻止发布。保留 SBOM 和许可证清单。
- 工具更新采用独立 manifest 和 feature flag，先 canary 后全量；新版本异常可回滚到上一份已验证二进制，不改动用户数据和外部模型配置。yt-dlp 因站点策略失效时显示“站点兼容性”错误，不引导用户下载非官方脚本。

## 7. 稳定性设计与故障矩阵

| 故障 | 用户看到的状态 | 自动动作 | 最终动作 | 禁止行为 |
| --- | --- | --- | --- | --- |
| 端口被占用 | “正在选择可用端口” | 探测并选择受控空闲端口 | 显示新访问地址 | 杀掉未知进程 |
| 前端启动失败 | “正在切换稳定前端” | 使用已构建静态资源 | 打开诊断日志 | 显示假成功 |
| 后端未就绪 | “后台正在启动” | 退避轮询 | 超时后给修复入口 | 允许提交任务 |
| ffmpeg 缺失 | “本地音视频需要安装” | 打开依赖向导 | 选择路径/下载 | 只禁用按钮不解释 |
| 外部模型配置错误 | “外部模型不可用” | 保留上一次可用配置 | 重新测试/切换提供商 | 把本地烟测当成模型可用 |
| 外部模型超时 | “长文本生成超时，可重试” | 按状态机最多重试 2 次 | 从 checkpoint 重试或人工确认 | 无限重试/重复扣费 |
| 数据库迁移失败 | “数据已保护，暂时只读” | 恢复备份探测 | 导出诊断包 | 强行继续写入 |
| 连接器写入失败 | “本地结果已保存，同步失败” | 退避重试 | 单独重试同步 | 丢弃本地结果 |
| 服务重启 | “正在恢复任务” | lease 回收 + reconciler 对账 | 自动恢复本地阶段；外部副作用需确认 | 让任务从历史消失 |

## 10. v2.0 对抗式五角色复评

本轮评审只检查 v2.0 新增契约能否消除上一轮的否决理由。每个角色先尝试阻断交付，再给出可验证的放行条件。

### 角色 A：普通客户 / 新手用户

**攻击点：** 外部模型是硬依赖时，我可能不知道为什么不能生成；端口和依赖错误不应要求我读日志。向导步骤多也会造成放弃。

**v2.0 证据：** 4.2 按资料类型只展示真正阻塞项；阶段 3 将完成页排除在操作数外，文档路径不超过 5 次点击/提交；4.1/6.1 在发送前解释提供商、数据类别和费用，未同意不会发请求；readiness 每个 blocker 提供一个动作。

**复评结论：通过（有明确前置）。** 必须在 Win10/11 干净机由未看 README 的测试者完成文档烟测 <=5 分钟，并证明未配置模型时生成入口不会伪装成成功。

### 角色 B：Windows 发布工程师

**攻击点：** 动态端口、杀毒误报、工具供应链和升级覆盖仍可能让安装包现场失败；模型不能因为“配置保留”而被误认为随包交付。

**v2.0 证据：** 4.3 定义 startup.json 原子写入、token 握手、未知 PID 不终止和双实例竞争测试；6.2 规定 250 MB 包体预算、SHA-256、SBOM、代码签名、manifest 回滚；3.1.1/验收矩阵明确只保留外部模型配置而无模型权重。

**复评结论：通过（有明确前置）。** 需在 Win10/11 x64 各完成安装、升级、卸载、端口冲突和 Defender 扫描记录；任一签名/哈希失败阻断发布。

### 角色 C：SRE / 稳定性工程师

**攻击点：** 进程崩溃、网络抖动或迁移中断可能重复扣费、重复写文档或使任务永远卡住。

**v2.0 证据：** 阶段 5 持久化 job/step/outbox，worker lease + 10 秒 heartbeat + 60 秒 stale 回收，阶段超时和最多 2 次重试；外部副作用未知时暂停人工确认；local PGlite 与 platform Postgres 分别加文件锁/advisory lock，并以同一 schema contract 校验。

**复评结论：通过（有明确前置）。** 故障注入必须证明强制关闭、网络切断、磁盘满、DDL 中断后任务可查询，重复副作用率为 0，SLO 表中的启动/丢失/误报指标达标。

### 角色 D：安全与合规负责人

**攻击点：** API Key、Cookie、原文、诊断包和工具更新仍可能泄漏或被篡改；用户需要可撤销的数据外发选择。

**v2.0 证据：** 6.1 使用 DPAPI/Credential Manager 引用而非明文，日志和 URL 字段级脱敏，Cookie 仅内存使用；consentId 记录策略版本并支持撤销；6.2 强制来源锁定、哈希、签名、SBOM 和包体阻断；诊断包敏感扫描失败即拒绝导出。

**复评结论：通过（有明确前置）。** 发布前须完成密钥/原文扫描、诊断包 20 例抽样、外发同意撤销测试和供应链签名审计；安全审计未签字不得交付。

### 角色 E：QA / 客服与现场支持

**攻击点：** 状态太多会让客服无法判断责任域；恢复操作若不可解释，用户会反复点击造成重复任务。

**v2.0 证据：** 4.1 固定状态和错误码，4.2 readiness 返回逐项依赖，阶段 5 暴露 checkpoint/费用/是否安全重试，6.1 诊断包包含时间线、runId/jobId、工具和迁移信息但不含敏感内容；SLO 要求责任域定位率 >=95%。

**复评结论：通过（有明确前置）。** QA/客服需用 20 个预置故障盲测诊断包，至少 19 个定位到环境、配置、网络、外部服务、数据或内部错误中的正确责任域，并完成一次恢复话术演练。

## 11. 最终交付判定

五个角色均未发现 v2.0 设计层面的阻断项，复评结论为“通过，但必须满足可验证前置条件”。本版本接受的产品取舍是：模型统一外部、安装包只含必要运行时和媒体工具；用配置向导、状态机、数据外发同意、持久化恢复和可观测 SLO 换取较小包体、较低供应链风险和更稳定的现场行为。

**客户版放行条件（全部满足）：** 14 周基线各阶段退出门槛完成；Windows 10/11 干净机测试记录齐全；双数据库迁移/恢复和故障注入通过；SLO 达标；安全审计签字；五角色复评证据归档。任一条件缺失只能发布内部试点版，不得对普通客户承诺开箱即用。

2. 冻结 `shared/api.interface.ts` 中的模型状态、readiness、job/outbox、迁移和端口握手契约。
3. 完成 P0-1/P0-2，交付签名、manifest、动态端口和外部模型配置，不实现本地 Whisper 新路径；现有本地 Whisper 仅保留 deprecated 兼容开关且默认关闭。
4. 完成 P0-3/P0-4，打通不依赖模型的文档烟测、依赖矩阵和 readiness。
5. 完成 P0-5，先做双库迁移 ledger，再做 lease、reconciler、outbox 和人工恢复界面。
6. 完成 P0-6，验证连接器失败不影响本地结果，并落实 DPAPI、consent 和诊断包脱敏。
7. 每个阶段执行 type check、lint、相关单测、接口/迁移/启动器测试；阶段 1/5/发布验证必须在真实 Windows 10/11 x64 完成。
8. 归档五角色复评证据和 SLO 报告后，才生成客户安装包和交付说明。
