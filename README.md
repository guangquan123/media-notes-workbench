> 范围说明：本文只描述当前多媒体笔记主流程。仓库中的实验性页面、旁路模块和历史方案，
> 不代表本产品的可用功能或交付承诺。

Media Notes Workbench 是一个本地优先的内容处理工作台。它把 B 站、抖音、本地视频、录音、
PDF、Word 和 PowerPoint 中的内容，整理为带原文依据、提示词快照、质量检查和后续任务的学习笔记，
并归档到当前启用的飞书或钉钉连接器。

项目关注的不是“生成一篇看起来完整的总结”，而是让每个结论都能回到输入资料，让每次处理都能
在历史记录中复盘，并能继续转化为待办行动。

## 快速入口

| 你手里的资料 | 从这里开始 | 你会得到 |
| --- | --- | --- |
| B 站或抖音视频链接 | [视频学习笔记](#处理一份学习资料) | 转录原文、结构化笔记、可选关键画面和连接器归档 |
| 本地课程、讲座或录屏 | [本地视频](#处理一份学习资料) | 提取音轨、转录、笔记和原文归档 |
| 课堂录音、访谈或语音备忘 | [录音笔记](#处理一份学习资料) | 重点、决策、行动项和可回看的转录 |
| 同一场内容的视频 + 独立录音 | [双源会议 / 培训](#双源会议--培训) | 时间对齐、双路转写、冲突清单和融合笔记 |
| PDF、Word 或 PowerPoint | [文档笔记](#文档笔记) | 多文件原文解析、来源边界和结构化笔记 |
| 手机里收藏的视频链接 | [飞书收集箱](#从手机收集视频链接) | 自动去重并创建视频学习笔记任务 |

## 为什么值得用

- **少整理一步**：下载或上传后，音频处理、转录、解析、总结和归档由一条任务链完成。
- **证据留在身边**：原文、来源文件指纹、解析质量和生成时使用的提示词一起保存。
- **把不确定性显式化**：真实性检查不能脱离原文补造事实；数字、术语和冲突会标记为待核对。
- **从笔记走向行动**：生成结果可同步到当前连接器的文档和待处理任务。
- **按环境选择成本**：音视频可选择本机 Whisper 或腾讯云 ASR；总结能力按实际配置决定是否调用云服务。

## 一次处理的闭环

~~~mermaid
flowchart LR
    A[视频 / 录音 / 文档] --> B[本机提取或解析]
    B --> C[转录原文与来源元数据]
    C --> D[依据补充与结构化笔记]
    D --> E[真实性与完整性检查]
    E --> F[飞书 / 钉钉文档]
    F --> G[待处理任务]
    F --> H[转化记录与复盘]
~~~

质量控制和人工复核是闭环的一部分，不是生成失败后的补救措施。系统不会自动替你对外发布内容，
也不会把无法确认的信息伪装成事实。

## 支持的入口与边界

| 入口 | 输入 | 处理结果 | 主要限制 |
| --- | --- | --- | --- |
| 视频学习笔记 | B 站、抖音视频链接 | 转录、学习笔记、可选关键画面、连接器文档 | 受限视频可能需要本机浏览器登录态 |
| 本地视频 | 本地视频文件，可多选 | 提取音轨、转录、笔记、原文归档 | 单个或累计不超过 10 GB，最多 10 个 |
| 录音笔记 | 本地音频文件 | 转录、笔记、原文归档 | 单个或累计不超过 10 GB |
| 双源会议 / 培训 | 一份主视频 + 一份辅助录音 | 时间对齐、双路转写、冲突清单、融合笔记 | 两份文件累计不超过 10 GB |
| 文档笔记 | PDF、Word、PowerPoint，可多选 | 文档解析、学习笔记、连接器归档 | 单个或累计不超过 200 MB，最多 10 个 |
| 提示词配置 | 学习笔记或会议纪要模板 | 草稿、发布版本、历史版本和差异 | 只有“发布生效”后的版本用于新任务 |
| 转化记录 | 历次任务 | 状态、原文、提示词快照、筛选和重处理 | 服务重启后运行中的任务不能恢复查询 |

所有远程资料都必须使用安全的 HTTPS 地址，禁止私网或 localhost 地址。只处理你有权访问、处理
和保存的资料。

## 处理方式

### 处理一份学习资料

1. 打开“参数配置”，完成连接器、输出位置和转录/总结模型的就绪检查。
2. 在首页选择平台视频、本地视频、录音、双源会议 / 培训或文档入口。
3. 粘贴视频地址，或上传本地文件；必要时选择学习笔记或会议纪要模板。
4. 提交任务，观察下载、解析、转录、生成、检查和归档阶段。
5. 完成后打开原文、笔记和待处理任务，人工核对结论、数字、术语与行动项。
6. 在“转化记录”中按类型、日期和状态筛选，完成复盘或重处理。

### 双源会议 / 培训

主视频负责画面和视频音轨，辅助录音补足语义。系统分别转写两路内容，根据声音能量变化计算时间
偏移，并将重叠片段标记为“双路一致”；只在一路出现的内容保留来源标记，数字、术语或表述冲突
会同时保留并标记“待核对”。

自动对齐无法达到可信阈值时，任务会停止融合，用户可以检查文件是否对应，或改用手动偏移重新提交。
辅助录音不能恢复原视频里已经丢失的像素、数字或表格细节。

### 文档笔记

文档入口不依赖本地 Whisper。系统解析 PDF、Word 或 PowerPoint，并在原文和笔记中保留每个来源文件
的名称、边界和指纹。扫描件、加密文件或解析内容过短的 PDF 应视为需要 OCR 或人工复核，而不是
完整可靠的原文。

## 快速开始

### 环境要求

| 组件 | 用途 | 必需性 |
| --- | --- | --- |
| Windows | 图形启动器和推荐的本地运行环境 | 推荐 |
| Node.js >= 22、npm >= 10 | 前后端运行时 | 必需 |
| 飞书或钉钉授权 | 文档、待办和连接器输出 | 至少配置一个 |
| ffmpeg | 音频提取、格式处理和切片 | 视频 / 录音必需 |
| yt-dlp | 获取 B 站、抖音视频 | 平台视频必需 |
| whisper-cpp + 本地模型 | 离线转录 | 与腾讯云 ASR 二选一 |
| 腾讯云 COS + ASR | 云端转录 | 可选，与本地 Whisper 二选一 |

视频和录音至少需要 `ffmpeg`，并在本机 Whisper 或腾讯云 ASR 中选择一种转录方式。文档笔记不需要
`ffmpeg`、`yt-dlp` 或语音转录引擎。

### 安装与启动

~~~powershell
npm.cmd install
npm.cmd run start:windows
~~~

也可以双击 [启动多媒体笔记工作台.vbs](启动多媒体笔记工作台.vbs)。默认访问地址为：

~~~text
http://localhost:8081/app/app_179bn4jet6k/
~~~

端口和子路径以 `.env.local` 中的 `SERVER_PORT`、`CLIENT_DEV_PORT`、`CLIENT_BASE_PATH` 为准。
服务日志写入 `logs/dev.std.log`，进程状态写入 `pids/`，这两个目录不应提交。

停止或重启本项目：

~~~powershell
npm.cmd run stop:windows
npm.cmd run restart:windows
~~~

### 环境检查

~~~powershell
node --version
npm --version
yt-dlp --version
ffmpeg -version
whisper-cli --help
lark-cli auth status --json --verify
dws auth status --format json
~~~

如果只处理文档，可以跳过 `yt-dlp`、`ffmpeg` 和 `whisper-cli` 检查。不要将 Cookie、飞书/钉钉令牌、
`.env.local`、原始媒体或临时文件提交到仓库。

## 从手机收集视频链接

1. 在飞书创建一个仅自己使用的群聊，例如“媒体收集箱”。不要把它用于多人聊天，因为该会话中的每条
   B 站或抖音链接都会进入处理队列。
2. 在电脑端打开“飞书收集箱”，填写该会话的 `oc_...` ID 并绑定。可用以下命令查询会话：

   ~~~bash
   lark-cli im +chat-search --as user --query 媒体收集箱 --format json
   ~~~

3. 绑定时已有消息只作为基线，之后的新链接才会进入队列。服务每 30 秒检查一次，也可以在页面手动同步。
4. 任务结果仍在“视频学习笔记”和“转化记录”中查看。

绑定信息和已处理消息 ID 只保存在本机 `.media-inbox-state.json`，电脑需要保持本机服务和飞书 CLI 授权状态。

## 可追溯性与合规

- **输入可回溯**：转换记录保存资料类型、标题、结果状态，并提供原文入口。
- **提示词可回溯**：每次生成记录提示词快照和版本，避免模板变化后无法解释旧笔记。
- **来源有边界**：主体内容只应来自转录或解析原文、资料元数据和明确带来源 URL 的补充材料。
- **人工在闭环中**：转录质量、AI 输出、外部补充、图片版权、隐私和最终分享都需要人工检查。
- **权限不越界**：飞书和钉钉一次只启用一个连接器；输出位置、待办执行人和访问权限以当前授权为准。

~~~text

  modules/connectors/           飞书 / 钉钉授权、文档与待办输出
  modules/note-inbox/           飞书链接收集箱与去重账本

  database/                     转换记录、提示词版本和迁移
~~~

运行中的任务状态保存在服务进程内存中，服务重启后尚未完成的任务不能继续查询；转换历史、提示词
版本和追溯数据使用项目数据库保存。实验性页面或旁路模块即使仍存在于仓库，也不改变本文产品范围。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 平台视频下载失败或 B 站 HTTP 412 | 链接是否有效；是否选择了已登录浏览器作为 Cookie 来源；`yt-dlp` 是否可用 |
| 转录无法开始 | `ffmpeg`、`whisper-cli` 和本地模型，或腾讯云 ASR 凭证、COS 桶和地域 |
| 无法创建飞书文档或待办 | `lark-cli auth status --json --verify`，以及当前账号对目标位置的权限 |
| 无法写入钉钉文档或待办 | `dws auth status --format json`，以及执行人配置 |
| 文档笔记很少或不完整 | 源文件是否为扫描件、加密文件或复杂排版；必要时先 OCR 并人工核对 |
| 修改提示词后样式未变化 | 保存后还要点击“发布生效”；草稿不会直接用于新任务 |
| 历史记录找不到 | 清除类型、日期和状态筛选；记录按生成时间倒序展示 |
| 本地页面打不开 | 查看 `logs/dev.std.log`，确认 `3000`、`8081` 端口属于本项目 |

服务就绪接口：

~~~text
GET /api/runtime
GET /api/note-jobs/readiness
~~~

## 当前边界

- 这是个人 / 本地内容工具，不是面向多人并发的生产级发布平台。
- 异步任务暂不具备服务重启恢复、队列调度、阶段重试和完整并发控制。
- 本地 Whisper 使用 CPU；长视频和大文件需要较长处理时间。启用云端 ASR 或外部总结模型时，相应内容
  会发送给对应云服务。
- 笔记质量受源文件、转录和文档解析质量影响；专业术语、数字、代码和图表需要重点复核。
- 不自动向外部平台发布内容，也不跟踪外部平台发布结果。
